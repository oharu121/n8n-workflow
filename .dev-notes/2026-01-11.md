# Supabase Port Comparison: 6543 vs 5432

## Overview

Supabase provides two connection modes via different ports. Choosing the wrong one can cause connection issues.

## Port Comparison

| Aspect | Port 6543 (Transaction Mode) | Port 5432 (Session Mode) |
|--------|------------------------------|--------------------------|
| **Mode** | Transaction pooling | Session pooling |
| **Connection behavior** | Different connection per query | Same connection for session |
| **Prepared statements** | Not supported | Supported |
| **Session state** | Not preserved | Preserved |
| **Best for** | Serverless, Lambda, Edge functions | Persistent apps, containers, VMs |
| **Connection lifetime** | Very short (per query) | Long-lived |

## When to Use Each

### Use Port 6543 (Transaction Mode)
- AWS Lambda functions
- Vercel Edge/Serverless functions
- Short-lived, stateless operations
- High connection throughput needs

### Use Port 5432 (Session Mode)
- n8n (requires prepared statements)
- Docker containers
- Traditional backend servers
- Applications needing session state
- ORM tools like Prisma (without special config)

## n8n Requirement

n8n **must use port 5432** because it:
- Uses prepared statements for database queries
- Maintains long-lived connections
- Expects session-level state between queries

Using port 6543 with n8n causes intermittent "Database is not ready!" errors because each query gets a different connection, breaking n8n's expectations.
